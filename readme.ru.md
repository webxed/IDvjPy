# IDvjPy_term

**(idi v jopy terminal)** — Терминальное приложение с текстовым интерфейсом (TUI) для тех, кто устал от старых способов взаимодействия с командной строкой. Построено на Python с использованием фреймворка Textual, предоставляет простой клавиатурный интерфейс для выполнения shell-команд и управления постоянной историей с тегами.

## Основные возможности

*   **Автоматическая загрузка базы**: При запуске приложения все команды автоматически загружаются в память, поэтому команда `!!` работает сразу без необходимости предварительного запроса.
*   **Двухпанельный интерфейс**: Знакомый макет с полем ввода команд сверху и прокручиваемой областью вывода снизу.
*   **Блочная организация вывода**: Каждая команда и её результат содержатся в отдельном блоке, который можно выделить.
*   **Навигация с клавиатуры**:
    *   `PageUp/PageDown` — перемещение фокуса между блоками команд
    *   `Up/Down` — навигация по истории команд текущей сессии
    *   `F5` — копирование содержимого выделенного блока в буфер обмена
    *   `Escape` — фокус на поле ввода
*   **Тегированная история**: Сохраняйте команды с тегами для быстрого доступа и повторного использования.
*   **Комментарии к командам и тегам**: Добавляйте описания к отдельным командам (`#tag=ID=comment`) и целым тегам (`#tag=comment`).
*   **Переменные окружения**: Создавайте и управляйте локальными переменными окружения.
*   **Поддержка пайпинга**: Передавайте вывод из одного блока в другую команду.

## Системные требования

*   Linux (тестировалось на Ubuntu/Debian)
*   Python 3.8+
*   Установленный `bash` в `/bin/bash`

## Установка

### Автоматическая установка

Запустите скрипт настройки:

```bash
./setup.sh
```

Этот скрипт:
1.  Создаст виртуальное окружение Python (`.venv`)
2.  Активирует виртуальное окружение
3.  Установит все необходимые зависимости
4.  База данных создастся автоматически при первом запуске

### Ручная установка

Если вы предпочитаете установить всё вручную:

```bash
# Создайте виртуальное окружение
python3 -m venv .venv

# Активируйте его
source .venv/bin/activate

# Установите зависимости
pip install -r requirements.txt
```

### Система команд

Приложение анализирует первый символ введённой команды для определения типа операции:

#### 1. Обычные shell-команды (без префикса)

Выполняет команду через shell и добавляет в историю сессии.

```bash
ls -la
grep "pattern" file.txt
find . -name "*.py"
```

**Особенности:**
-   Команды выполняются в `/bin/bash` с поддержкой алиасов из `~/.bashrc`
-   Таймаут выполнения: 10 секунд (настраивается в `settings.yml`)
-   Вывод отображается в отдельном блоке с кодом возврата

#### 2. Сохранение с тегом (`#tag`)

Сохраняет команду в базу данных с указанным тегом.

```bash
#deploy systemctl restart nginx
#backup rsync -av /data /backup
#test python -m pytest tests/
```

#### 3. Удаление по тегу (`#tag-` или `#tag-tid`)

```bash
#deploy-                 # Удалить все команды с тегом 'deploy'
#deploy-2                # Удалить команду deploy[2]
```

Команды помечаются как удалённые (soft delete).

#### 3.1. Комментарии к тегам (`#tag=комментарий`)

Добавляет описание к тегу для быстрого понимания его назначения.

```bash
#deploy=Production server commands
#test=Unit and integration tests
#backup=Daily backup routines
```

Комментарии отображаются при просмотре списка тегов (`?`) и команд (`?*`, `?tag`).

#### 3.2. Комментарии к командам (`#tag=ID=комментарий`)

Добавляет описание к конкретной команде с указанным тегом и локальным ID.

```bash
#deploy=1=Update nginx configuration
#test=2=Fix authentication bug
#backup=3=Incremental backup of user data
```

Комментарии к командам отображаются при просмотре всех команд (`?*`) или команд по тегу (`?tag`).

**Пример использования:**

```bash
# Сначала сохраняем несколько команд
#deploy systemctl restart nginx
#deploy nginx -t
#deploy systemctl reload nginx

# Добавляем комментарии к командам
#deploy=1=Full restart of nginx
#deploy=2=Check nginx configuration
#deploy=3=Reload nginx without downtime

# Просматриваем команды с комментариями
?deploy
# Вывод:
# Commands for tag 'deploy':
#   [1] deploy[1]  systemctl restart nginx  # Full restart of nginx
#   [2] deploy[2]  nginx -t  # Check nginx configuration
#   [3] deploy[3]  systemctl reload nginx  # Reload nginx without downtime
```

#### 4. Поиск команд (`?`)

```bash
?                       # Список всех тегов
?*                      # Все команды сгруппированные по тегам
?deploy                 # Все команды с тегом 'deploy'
```

Результаты запроса сохраняются для выполнения через `!`.

#### 5. Выполнение по ID (`!tag[tid]` или `!ID`)

Выполняет команду из базы данных. Поддерживает два формата:

**Новый формат (v1.1.0+):** `!tag[tid]` — по имени тега и локальному ID

```bash
?deploy
# Вывод:
# [1] deploy[1] systemctl restart nginx
# [2] deploy[2] nginx -t
# [3] deploy[3] systemctl reload nginx

!deploy[1]              # Выполнить "systemctl restart nginx"
!deploy[3]              # Выполнить "systemctl reload nginx"
```

**Старый формат:** `!ID` — по глобальному ID (обратная совместимость)

```bash
!1                      # Выполнить команду с глобальным ID 1
!5                      # Выполнить команду с глобальным ID 5
```

**Преимущества нового формата:**
-   Наглядность: сразу видно имя тега и номер команды внутри тега
-   Удобство: не нужно запоминать глобальные ID
-   Организация: команды автоматически нумеруются внутри каждого тега

#### 6. Сборка команд по ID (`!!ID1 ID2 ID3`)

Собирает несколько команд в одну строку с разделителями и вставляет в поле ввода.

**Поддерживаемые форматы ID:**
- Числовой: `1`, `2`, `3` (глобальный ID)
- Теговый: `deploy[1]`, `test[2]` (тег + локальный ID)
- Смешанный: можно комбинировать оба формата

```bash
# Использование с глобальными ID:
!! 1 3                      # Вставить команды с ID 1 и 3

# Использование с теговым форматом tag[tid]:
!! deploy[1] deploy[2]      # Вставить две команды из тега deploy
!! deploy[1];deploy[3]      # Вставить: systemctl restart nginx ; nginx -t
!! deploy[1]|backup[2]&&deploy[3]  # Комбинировать команды из разных тегов

# Смешанный формат (глобальный ID + tag[tid]):
!! 1;deploy[2]&&test[3]     # Комбинировать числовые и теговые ID
```

**Поддерживаемые разделители:**
-   Пробел — команды выполняются последовательно
-   `;` — последовательное выполнение (всегда)
-   `&&` — выполнение следующей, если предыдущая успешна
-   `||` — выполнение следующей, если предыдущая неудачна
-   `|` — передача вывода в следующую команду
-   `>` / `<` — перенаправление вывода

**Особенности:**
-   **База команд загружается автоматически при старте приложения** - можно сразу использовать `!!`
-   Команда вставляется в строку ввода (нажмите Enter для выполнения)
-   Можно редактировать команду перед выполнением
-   Поддерживаются оба формата ID одновременно в одной команде `!!`
-   Если ID не найден — выводится ошибка с указанием проблемного ID
-   После выполнения запроса (`?*` или `?tag`) список ID обновляется

#### 7. Команды приложения (`:`)

Встроенные команды управления приложением.

```bash
:q                      # Выйти из приложения
:w output.txt           # Записать все блоки в файл
:h                      # Показать последние 20 команд из history.txt
:h 50                   # Показать последние 50 команд
```

#### 8. Пайпинг из блока (`|command`)

Использует stdout из сфокусированного блока как stdin для новой команды.

```bash
# Допустим, предыдущая команда "ls -la" выдала список файлов
| grep ".py"            # Передать вывод ls в grep
| wc -l                 # Посчитать количество строк
```

**Важно:** Фокус должен быть на блоке команды (нажмите `PageUp/PageDown` для выделения).

#### 9. Переменные окружения (`$VAR=value`)

Создаёт или обновляет локальную переменную окружения.

```bash
$PROJECT=/home/user/projects/myapp
$EDITOR=nvim
$API_KEY=secret123
```

Переменные:
-   Сохраняются в файл `.bashrc_term` в корне проекта
-   Добавляются в окружение текущего процесса
-   Имеют приоритет над системными переменными
-   Могут использоваться в командах: `echo $PROJECT`

### Горячие клавиши

| Клавиша   | Действие                        |
|-----------|---------------------------------|
| `Up`      | Предыдущая команда в истории    |
| `Down`    | Следующая команда в истории     |
| `PageUp`  | Фокус на предыдущий блок        |
| `PageDown`| Фокус на следующий блок         |
| `F5`      | Копировать блок в буфер обмена  |
| `Escape`  | Фокус на поле ввода             |
| `d`       | Переключить тёмную тему         |

### Подстановка переменных

Переменные автоматически подставляются в командах:

```bash
$MYDIR=/tmp
cd $MYDIR          # → cd /tmp

$EDITOR=nvim
$EDITOR file.txt   # → nvim file.txt
```

**Приоритет подстановки:**
1.  Локальные переменные (из `$VAR=value`)
2.  Системные переменные окружения (`os.environ`)
3.  Если переменная не найдена — оставляется как `$VAR` (shell сам сообщит об ошибке)

### Алиасы bash

Приложение автоматически загружает алиасы из `~/.bashrc` при запуске:

```bash
# В ~/.bashrc:
alias ll='ls -la'
alias gs='git status'

# В приложении:
ll               # Работает!
gs               # Работает!
```

## Файлы и настройки

### settings.yml

Файл конфигурации в корне проекта:

```yaml
max_lines: 100000           # Максимальное количество строк в буфере вывода
history_lines: 20           # Количество строк для команды :h (по умолчанию)
database_tags_file: exeds_tags.db  # Имя файла базы данных
command_timeout: 10         # Таймаут выполнения команд (секунды)
```

### .bashrc_term

Файл для хранения локальных переменных окружения. Создаётся автоматически при первом использовании команды `$VAR=value`.

Формат:
```bash
# Terminal-specific environment variables
export MYVAR="1"
export PROJECT="/home/user/app"
```

### history.txt

Файл с историей команд текущей сессии. Не включает специальные команды (префиксированные `:`, `?`, `!`, `#`, `|`, `$`).

### history_v2.db (или другое имя из settings)

SQLite база данных для хранения тегированных команд с поддержкой tag-local ID, комментариев к тегам и комментариями к командам.

**Структура таблицы `commands`:**

| Поле      | Тип       | Описание                              |
|-----------|-----------|---------------------------------------|
| id        | INTEGER   | Глобальный уникальный ID (автоинкремент) |
| tag       | TEXT      | Тег команды                           |
| tid       | INTEGER   | Локальный ID внутри тега (автоинкремент) |
| command   | TEXT      | Текст команды                         |
| timestamp | DATETIME  | Время создания                        |
| deleted   | INTEGER   | Флаг удаления (0 = активна, 1 = удалена) |
| comment   | TEXT      | Комментарий к команде                 |

**Структура таблицы `tags`:**

| Поле    | Тип  | Описание                   |
|---------|------|----------------------------|
| tag     | TEXT | Имя тега (PRIMARY KEY)     |
| comment | TEXT | Комментарий к тегу         |

**Уникальность:** (tag, tid) — каждая комбинация уникальна

## Архитектура

### Основные компоненты

**[app.py](app.py)** — Главный файл приложения (~900 строк)

-   `CommandRunner` — Основной класс приложения (наследует `App` из Textual)
-   `CommandBlock` — Виджет для отображения вывода команды
-   `InfoBlock` — Виджет для информационных сообщений

**Ключевые методы CommandRunner:**
-   `on_mount()` — Инициализация приложения, загрузка настроек, БД, переменных
-   `_populate_query_results()` — Автоматическая загрузка команд при старте (v1.1.2+)
-   `handle_save_command()` — Парсинг и сохранение команд с тегами и комментариями
-   `handle_query_command()` — Поиск команд с поддержкой комментариев
-   `handle_bang_command()` — Выполнение команд по ID (поддерживает два формата)
-   `handle_double_bang_command()` — Сборка нескольких команд с разделителями

**[database_v2.py](database_v2.py)** — Модуль работы с базой данных (v2)

-   `init_db()` — Создание таблиц с автоматической миграцией
-   `add_command()` — Сохранение команды с auto-increment tid
-   `delete_commands_by_tag()` / `delete_command_by_tid()` / `delete_command_by_global_id()` — Soft delete
-   `get_all_tags()` / `get_commands_by_tag()` / `get_all_commands_with_ids()` — Запросы с комментариями
-   `set_tag_comment()` / `get_tag_comment()` — Комментарии к тегам (v1.1.1+)
-   `set_command_comment()` / `get_command_comment()` — Комментарии к командам (v1.1.2+)

**[app.css](app.css)** — Стилизация Textual интерфейса

### Жизненный цикл приложения (v1.1.2+)

1. **Инициализация (`on_mount`)**:
   - Загрузка настроек из `settings.yml`
   - Инициализация БД (создание таблиц/миграция)
   - Загрузка переменных из `.bashrc_term`
   - Загрузка алиасов из `~/.bashrc`
   - **Автоматическая загрузка всех команд** (`_populate_query_results`)

2. **Отображение (`on_ready`)**:
   - Приветственное сообщение с версией

3. **Основной цикл**:
   - Приём команд от пользователя
   - Маршрутизация по префиксам (`#`, `?`, `!`, `!!`, `|`, `$`, `:`)
   - Выполнение в фоновых потоках
   - Обновление UI через `call_from_thread`

### Потоковое выполнение

Команды выполняются в отдельных потоках (`threading.Thread`) чтобы не блокировать UI:

```python
thread = threading.Thread(
    target=self._execute_in_thread,
    args=(block, final_command, stdin_data),
    daemon=True
)
thread.start()
```

После завершения поток обновляет блок через `call_from_thread()`.

## Устранение неполадок

### "Missing dependency" при запуске

Не установлены зависимости. Выполните:

```bash
pip install -r requirements.txt
```

### Команда не выполняется, "Process timed out"

Команда требует более 10 секунд (настрой по умолчанию) или интерактивного ввода.

**Решения:**
1.  Увеличьте таймаут в `settings.yml`:
    ```yaml
    command_timeout: 30
    ```
2.  Используйте неинтерактивные флаги:
    ```bash
    apt install -y package  # Вместо интерактивного apt install
    ```

### Алиасы не работают

Убедитесь, что `~/.bashrc` существует и читается приложением. Алиасы загружаются при запуске через `source ~/.bashrc`.

### Буфер обмена не работает (F5)

На Linux требует установки `xclip` или `xsel`:

```bash
sudo apt install xclip
# или
sudo apt install xsel
```
