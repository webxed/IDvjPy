# План развития IDvjPy_term

Каждая задача ведётся в отдельной **локальной** ветке. Ветки не отправляются на `origin`: после проверки изменения будут последовательно влиты в `main` и только затем опубликованы.

| № | Ветка | Подзадача |
|---:|---|---|
| 1 | `feature/01-safe-mode` | **Готово.** Опциональный режим безопасности: понятное подтверждение потенциально мутирующих команд и опасных `run:auto`; не подменяет shell. |
| 2 | `feature/02-doctor` | **Готово.** `:doctor`: локальная диагностика утилит, зависимостей, путей данных, языка, scope, clipboard, терминала, proxy и shell helper. |
| 3 | `feature/03-explain` | **Готово.** `:explain` — локальная статическая эвристика для назначения программы, известных флагов, ожидаемого эффекта и признаков риска; команду не запускает. Не shell-парсер и не доказательство безопасности. |
| 4 | `feature/04-learn` | **Готово.** `:learn` — три офлайн read-only урока (Git status, TCP listening sockets, SQLite SELECT): пользователь запускает команду сам, `hint` даёт прогрессивные подсказки, `check` проверяет только форму и код выхода последнего нового блока. Это не проверка произвольного вывода и не песочница. |
| 5 | `feature/05-tag-metadata` | **Готово.** Метаданные тегов и фильтруемый каталог: риск, утилиты, ОС, интерактивность, тема и пример; SQLite migration, JSON transfer и `:tags` / `:tagmeta`. |
| 6 | `feature/06-pins` | **Готово.** Избранные/закреплённые теги для быстрого доступа (`:pin`), отдельный per-session JSON-файл, каталог `:tags pinned`; общая SQLite-библиотека и scope не мутируются. |
| 7 | `feature/07-profiles` | **Готово.** Профили окружений (`:profile`) хранят безопасные ссылки на cwd, scope, namespace и Kubernetes context в приватных JSON-файлах; значения секретов и vault не сохраняются. |
| 8 | `feature/08-snapshots` | **Готово.** Ограниченные по размеру снимки вывода и сравнение повторных результатов с правилами исключения строк. |
| 9 | `feature/09-history-search` | **Готово.** `:h tags /text` ищет по живым командам и комментариям SQLite-библиотеки, показывает вставляемые ссылки без запуска; `:h /text` остаётся поиском по истории сессии. Порядок сессионной истории не меняется. |
| 10 | `feature/10-library-sources` | Статические HTTPS-источники библиотек с preview, dry-run, подтверждением и без автоперезаписи. |
| 11 | `feature/11-export-signatures` | **Оценено — отложено.** Полноценная подпись требует модели доверия и управления публичными ключами; один hash/HTTPS подтверждает целостность передачи, но не автора. Не добавляем криптозависимость без согласованного keyring-контракта. |
| 12 | `feature/12-backup-management` | Список, восстановление, retention и backup перед значимыми мутациями через существующие механизмы. |
| 13 | `feature/13-library-audit` | **Готово.** Append-only `library_audit.jsonl` и `:audit [N]`: UTC-время, действие, число строк и имена тегов; явные импорты, пользовательские сохранения/комментарии, soft-delete и restore. Содержимое команд, комментариев, payload, URL и секретов не записывается; seed/внутреннее обслуживание исключены. Это операционный журнал, не tamper-proof аудит. |
| 14 | `feature/14-tag-validation` | Предупреждения до сохранения: ссылки/циклы, переменные, рискованные директивы и вероятные ошибки shell. |

## Правила выполнения

- Реализация идёт по порядку; каждая задача получает собственные тесты, документацию и отдельный commit/version bump после готовности.
- Ветка задачи — изолированная рабочая область. До её слияния последующие ветки не получают её API автоматически; при необходимости они перебазируются на актуальный `main`.
- Никакой новый механизм не должен выполнять импортированные или потенциально опасные команды автоматически.
- Секреты `$$` и `:vault` не включаются в логи, историю, экспорт, аудит или диагностические отчёты.
