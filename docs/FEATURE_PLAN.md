# План развития IDvjPy_term

Каждая задача ведётся в отдельной **локальной** ветке. Ветки не отправляются на `origin`: после проверки изменения будут последовательно влиты в `main` и только затем опубликованы.

| № | Ветка | Подзадача |
|---:|---|---|
| 1 | `feature/01-safe-mode` | Опциональный режим безопасности: понятное подтверждение потенциально мутирующих команд и опасных `run:auto`; не подменяет shell. |
| 2 | `feature/02-doctor` | `:doctor`: локальная диагностика утилит, зависимостей, путей данных, языка, scope, clipboard, терминала, proxy и shell helper. |
| 3 | `feature/03-explain` | `:explain` для локального разбора назначения команды, флагов, ожидаемого эффекта и риска; никаких запусков команды. |
| 4 | `feature/04-learn` | Учебный режим: задача, подсказки по запросу, команда пользователя и проверка реальным read-only инструментом. |
| 5 | `feature/05-tag-metadata` | Метаданные тегов и фильтруемый каталог: риск, утилиты, ОС, интерактивность, тема и пример. |
| 6 | `feature/06-pins` | Избранные/закреплённые теги для быстрого доступа, отдельно от общей SQLite-библиотеки и scope. |
| 7 | `feature/07-profiles` | Профили окружений: cwd, scope, namespace и прочие ссылки на контекст; значения секретов остаются только в `:vault`. |
| 8 | `feature/08-snapshots` | Ограниченные по размеру снимки вывода и сравнение повторных результатов с правилами исключения строк. |
| 9 | `feature/09-history-search` | Улучшенный поиск истории/библиотеки и статистика без нарушения хронологии сессионной истории. |
| 10 | `feature/10-library-sources` | Статические HTTPS-источники библиотек с preview, dry-run, подтверждением и без автоперезаписи. |
| 11 | `feature/11-export-signatures` | Оценить и при оправданности добавить необязательную проверку целостности/подписей экспортов доверенными ключами. |
| 12 | `feature/12-backup-management` | Список, восстановление, retention и backup перед значимыми мутациями через существующие механизмы. |
| 13 | `feature/13-library-audit` | Секретобезопасный аудит изменений библиотеки, импортов, soft-delete и восстановления. |
| 14 | `feature/14-tag-validation` | Предупреждения до сохранения: ссылки/циклы, переменные, рискованные директивы и вероятные ошибки shell. |

## Правила выполнения

- Реализация идёт по порядку; каждая задача получает собственные тесты, документацию и отдельный commit/version bump после готовности.
- Ветка задачи — изолированная рабочая область. До её слияния последующие ветки не получают её API автоматически; при необходимости они перебазируются на актуальный `main`.
- Никакой новый механизм не должен выполнять импортированные или потенциально опасные команды автоматически.
- Секреты `$$` и `:vault` не включаются в логи, историю, экспорт, аудит или диагностические отчёты.
