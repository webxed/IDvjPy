## P1 — согласованность данных и безопасность

### [x] 1. Согласовать каталог резервных копий при `--db`

**Подтверждено воспроизведением.** `src/backup_db.py:52–64,202–206` вычисляет каталог переноса по `settings.yml` каталога данных независимо от `--db`. При этом SQLite-снимок создаётся через `seed_lib.backup_sqlite`, которая выбирает настройки рядом с переданной базой (`src/seed_lib.py:74–83`). В результате `backup_db.py backup --db ...` может положить SQLite-снимок и JSON/CSV в разные каталоги, а `restore` искать файл не там, где пользователь ожидает. `backup_db.md:6–7` сейчас обещает настройки и `backups/` рядом с `--db`, но CLI этому обещанию не следовал.

**Сделано:** `load_backup_dir(db_file=None)` в `src/backup_db.py` при явном `--db` делегирует в `seed_lib.backup_dir_for(db_file)` — тот же resolver, что у SQLite-снимка; второй реализации путей нет. `main()` передаёт путь только когда `--db` задан. Тест: `tests/test_backup_cli.py::test_explicit_db_takes_settings_and_backups_next_to_it` (снимок и JSON лежат рядом с базой и её `settings.yml`).

**Осталось:** сквозные тесты `restore`/`import` при раздельных каталогах данных и базы, сверка формулировок `backup_db.md`.

### [x] 2. Проверить невозможность HTTPS → HTTP → HTTPS при импорте

**Подтверждено по коду.** `net.open_url` собирал opener без обработчика redirect-схем: `urlopen` следовал переходам сам, а проверка в `remote_source` смотрела только начальный и конечный URL. Проход через HTTP без `--insecure` был возможен.

**Сделано:** в `src/net.py` добавлены `allowed_redirect_schemes()`, `SchemeCheckingRedirectHandler` (проверяет схему **до** каждого перехода, включая промежуточные) и параметр `open_url(..., extra_schemes=)`; opener теперь всегда собирается через `build_opener` с этим обработчиком. `src/remote_source.py` передаёт `SUPPORTED_SCHEMES if allow_insecure else SECURE_SCHEMES`. **Продолжение (нашёл CI):** `src/llm_client.py` и `src/cheat_sh.py` держали **свои** копии `urlopen`/`build_opener` и обходили guard — ключ LLM-провайдера мог уехать по `https → http`. Оба `_open_request`/`_open` теперь делегируют в `net.open_url` (одна реализация сетевого слоя). Тесты: `tests/test_net.py` — `test_allowed_redirect_schemes_never_downgrade_to_http`, `test_redirect_handler_refuses_http_hop`, `test_open_url_installs_scheme_guard`, `test_all_outbound_calls_share_the_guarded_transport`; `tests/test_llm.py` и `tests/test_update_check.py` подменяют seam транспорта, а не `urllib.request.urlopen` (без внешней сети).

**Осталось:** тест цепочки HTTPS → HTTP → HTTPS на подменённом транспорте и проверка, что ошибки не печатают прокси-секреты.

## P2 — устойчивость и предсказуемость

### [ ] 3. Ограничить потребление памяти выводом фоновых команд

**Подтверждено статически; влияние нагрузкой не измерялось.** `src/app.py:11908–11932` собирает stdout и stderr через `Popen.communicate()` до завершения процесса; `:watch` аналогично использует `communicate()` (`src/app.py:13103–13107`). Большой или бесконечный поток может исчерпать память раньше таймаута, особенно при `command_timeout: 0` или `@ cmd`.

**План:**
- Измерить память и отклик на контролируемых генераторах в изолированной среде; проверить F4, timeout, stdout и stderr одновременно.
- Спроектировать ограниченное чтение или безопасный spool с явным сообщением об усечении; не ломать `$OUT`, pipe из сфокусированного блока, `:o`, поиск и маскирование секретов. Не писать открытые секреты во временные файлы.
- Добавить тесты большого вывода, очистки процессов и файлов, границы лимита и нескольких параллельных команд. Критерий: ограниченное потребление памяти и отзывчивый TUI.

### [ ] 4. Согласовать настройки для базы вне каталога данных

Это не обязательно неверная политика для явного `--db`, но для базы из настройки каталога данных поведение требует согласования и тестов.
