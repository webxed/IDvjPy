# AGENTS.md

Инструкции для агентов, которые меняют **IDvjPy_term** (репозиторий [webxed/IDvjPy](https://github.com/webxed/IDvjPy)).

Архитектура и карта модулей — в [`CLAUDE.md`](CLAUDE.md). Поведение для пользователя — [`README.md`](README.md), [`COMPACT_SUMMARY.md`](COMPACT_SUMMARY.md), в TUI — `:?`.

## Тарифы на использование (для агентов)

- **Непиковое время вдвое дешевле пикового** (вне пика — половина пикового тарифа).
- **Часы пик:** с **01:00 до 04:00** и с **06:00 до 10:00 UTC**, понедельник–пятница. Все остальные часы (включая выходные) — непиковые.
- **Время проверяй, а не угадывай.** Перед любым выводом про тариф — `date -u` в этом же шаге (окна 01:00–04:00 и 06:00–10:00 UTC, только будни). Не переносить «сейчас пик» из предыдущего ответа или из своей памяти: сессия живёт часами, окно давно могло закрыться.
- **Если запрос пользователя пришёл в пиковое время** — перед началом длительной или дорогой работы (большая серия правок, полный прогон тестов, много итераций) спроси, продолжать ли сейчас или отложить до непикового окна. В непиковое время действуй без лишних пауз.
- Не превращать это в лишние вопросы для коротких задач — вопрос только перед заметными по стоимости операциями.
- **Про тариф — молча.** Упоминать пик/непик в ответе можно **только** когда спрашиваешь разрешение на дорогую операцию (и то один раз). В обычных отчётах, итогах и объяснениях «почему не запустил полный прогон» про тариф не писать — это шум.

## Что это

Клавиатурный TUI на Textual: теги — **переменные с шаблонами команд**, приложение **собирает** из них строку. Слоган: *Define your variables, join your command.*

Это не «ещё один shell» и не IDE. Обычный Enter гоняет команду в журнал. Настоящий TTY — только `> cmd` (`htop`, `vim`, `ssh`).

Приложение **учебное**: оно часть освоения профессии DevOps. Поэтому инструменты показываются настоящие (`git`, `kubectl`, `helm`, `sqlite3`, `ocrmypdf`, …), а не прячутся за своими обёртками: справочник и справка должны учить самой команде и её смыслу — что делает флаг, что вернёт запрос, что изменится. Работа с базами — такая же часть навыка: справочник `sqlite` ставит SQL на **живую** базу библиотеки (`SELECT`, `GROUP BY`, `LIKE`, `EXPLAIN QUERY PLAN`, `DELETE`, `VACUUM`), а не на выдуманную песочницу. При улучшениях держать это в виду: новая возможность — повод показать реальный инструмент, а не спрятать его.

Параллельный порт `Idivjopy_rust` — другой репозиторий. Не трогать, пока явно не попросили.

## Принципы

1. **Собрал — потом запустил.** `!tag[tid]`, `!N`, `!!` только подставляют текст во ввод. Запуск — отдельным Enter. Не выполнять команду в том же шаге, что и подстановку. Единственное исключение — мышиное ускорение: **Ctrl+клик / двойной клик** по ссылке `!tag[tid]` в `??` вставляет и сразу выполняет (то же, что набрать ссылку и дважды нажать Enter); клавиатурный путь не меняется.
2. **Сохраняй литерал.** `#tag cmd` пишет текст как есть. Ссылки `!…` раскрываются при `?tag[tid]` и при выполнении, не при save.
3. **Код и данные разделены.** Код в `src/`. Корневые `app.py` / `backup_db.py` — лаунчеры. Данные живут в **каталоге данных** (`--data-dir` → `$IDVJPY_DATA_DIR` → каталог запуска, если в нём есть `settings.yml` → системный, на Linux `~/.config/idvjpy`): `settings.yml`, `mytags.db`, `.bashrc_term*`, `history_<instance>.txt`. Каталог запуска и каталог данных — не всегда одно и то же: алиас вида `idvjpy=~/WibeCoding/Idivjopy/app.py`, запущенный из `~`, оставляет данные в `~/.config/idvjpy`, а сиды читают `settings.yml` из cwd — их запускают из каталога данных (или с `--db`). `:cd` / `cd` меняют cwd только для shell-команд, не переносят и не создают эти файлы. Не писать рабочую БД и историю в git.
4. **Два хранилища — две роли.** SQLite — библиотека тегов. `history_*.txt` — лента того, что вводили. **Лента сессии (↑) и файл расходятся:** по ↑ перелистывается всё, что набрано в этой сессии (`:`-команды, `?теги`, `!ссылки`, `#теги`, `$VAR=…` — `_remember_session_line`), а в файл попадает только разрешённое (`log_to_history`: список `history_queries`, сохранения `#tag`, подстановки — мимо). Секреты (`$$…`) не попадают ни туда, ни туда. **Порядок ↑ — хронология набора** (`_history_pool_pairs`): сначала строки файла, которых в этой сессии не набирали, затем лента сессии целиком — иначе строка без файла (`:…`) всплывала бы выше обычной команды, набранной после неё. Не сливать историю сессии в базу тегов «ради скорости».
   **Секреты не ходят по ящику `:send`:** в пересылаемой команде остаётся имя `$NAME`, а значение уходит в секретное хранилище цели (`secrets_<target>.json`, 0600) и только если своего значения у неё нет (`CommandRunner._pass_secrets_to`) — получатель перечитывает файл при выемке ящика. Значение секрета не должно появляться ни в `inbox_*.jsonl`, ни в `history_*.txt`, ни в журнале — это инвариант, а не деталь реализации.
      **Маскировка замораживается в момент записи вывода** (`CommandBlock.freeze_secrets`): текст блока прячет значения теми секретами, которые были живы, когда вывод записан. Поэтому `$$NAME-`, переопределение, `:env` и `:session` не раскрывают уже показанное при повторном рендере (space/←→, F8, F2, поиск `:/`, `:w`), `:o` хранит уже замаскированный вывод, а `.bashrc_term` не может подменить значение секрета (`load_bashrc` пропускает имена из `_secret_names`). Хранилище при выходе чистится **только своё** (`secrets_<instance>.json*`) — соседняя сессия свои значения не теряет. Явные исключения — действия, которые человек запросил сам: `F3`, `:log`/F7 и `:cmd`/`:cmd show` отдают настоящий вывод/команду (в `:?` и README это указано; `:cmd` при `clear_clipboard_after_secret: true` в буфер значение не кладёт).
5. **Свои теги, чужие не трогать.** Каждый `--seed` перезаписывает только свой набор. `seed_ops.py` не трогает linux / k8s / git. Не затирать соседние handbook-теги (`net`, `file`, `proc`, …). Перед заменой — снимок SQLite в `backups/` (пустую БД не копировать; `seed_ops` — один файл, не по модулю).
6. **Сначала осмотр.** В seed-плейбуки — inspect (`get`, `status`, `dry-run`, query). Мутации (`install`, `delete`, `chmod` в плейбуке, бесконечный `strace -p`) — нет. Интерактив — `> cmd`.
   В цепочках для `:run` (директивы `run:` в комментариях) мутирующий шаг — только `run:manual`: человек видит строку и сам подтверждает Enter (так сделан выпуск `secret_id` в `vapprole`).
7. **UI не блокировать.** Shell-команды в потоках. Модалки (JSON, Markdown) сами едят колесо и клавиши, журнал под ними не скроллить.
8. **Клавиатура важнее мыши.** Новый сценарий должен работать без клика. Мышь (`terminal_mouse`) — ускорение: фокус блока, `--seed` во ввод, `.md` → `:md`.
9. **Мягкое удаление.** `#tag-` / `#name--` — soft-delete. Жёстко стирать из БД только то, что уже так устроено (сброс demo-тегов перед `--demo`).
10. **Недавнее — лента, старое — каталог.** Хвост `history_keep` не уникализировать. Компакт только старого префикса (`:h compact` / авто при длине `> 2 × history_keep`).
11. **Версия = коммит.** Каждый коммит поднимает минор `CommandRunner.VERSION` (`v1.171` → `v1.172`). `:update` сравнивает эту строку с `src/app.py` на GitHub `main`. Релизов/тегов на GitHub может не быть — источник правды для обновления именно `VERSION`.
    - Разом обновить версию во всех файлах: `python3 bump_version.py` (минор +1; `--dry-run` — показать diff, `--check` — проверить, `--set vX.YY` — явно). Секция changelog в `COMPACT_SUMMARY.md` добавляется заглушкой — впиши текст изменений.
12. **Сеть — только на чтение, ссылка — только https.** Исходящие запросы идут через `src/net.py` (прокси с логином: `$PROXY_USER` / `$PROXY_PASS`, подсказка при «407»); портов приложение не слушает. `:import <url>` берёт чужой JSON: по умолчанию только `https://` (`--insecure` — явный выбор), лимит 2 МБ, таймаут 10 с. В библиотеку ничего не пишется без второго Enter (`:import <url> --yes` подставляется во ввод, как `!tag[tid]`), payload со значением живого `$$`-секрета отклоняется, а про `run:`-директивы (шаги `auto` выполнит `:run` без подтверждения) план предупреждает. Ссылку по умолчанию задаёт `library_url` в `settings.yml` (пусто — выключено).
    **`:md` документы (docx/pdf/…) — офлайн.** `src/md_convert.py` предпочитает `anydoc` (`pip install firecrawl-anydoc`, Rust, без зависимостей), зовёт его импортом **без** `ocr` — скан-PDF получает `needs_ocr`, а не отправку в облако; остальные конвертеры — только локальные процессы (`markitdown`, `pandoc`). **Скан-PDF распознаётся локальным `ocrmypdf`** (`md_ocr` в settings.yml: пусто — автопоиск, `off` — выключить, или своя команда; нужен tesseract и языковой пакет — `tesseract-ocr-<язык>`), `ocr="hosted"` у anydoc не используем. Ничего не скачивать и не отдавать наружу: конвертация — часть `:md`, а не сетевой источник.

## Исследование кода

- **Сначала структура, потом исходники.** При исследовании кода всегда предпочитай `codegraph query <символ>` (поиск символов) и `codegraph context <задача>` — у `context` флаг `--no-code` отдаёт только структуру, без кода.
- **`codegraph explore` — только когда действительно нужен исходный код** символа, а не его расположение и связи.
- Остальное по надобности: `codegraph node <символ>` (исходник + вызывающие/вызываемые), `callers` / `callees` / `impact`, `files`, `status`; после больших правок — `codegraph sync` (или `index` для полной пересборки).

## Как менять код

- Новое поведение — префикс, клавиша или `:команда`, согласованные с таблицей в `CLAUDE.md`. Не плодить скрытые жесты.
- Пользовательские сообщения: коротко, без сюрпризов. Ошибка явная (`not found`, `Usage:`), не молчаливый fallback (`:i list -n` без namespace). Текст берётся из каталога локалей, не из литералов: `t("kctx.off")` → `src/locales/en.yml` (источник правды) и части `src/locales/<lang>/*.yml` (глубоко сливаются); длинные документы (справка `:?`) — файлами `src/locales/help/<lang>/*.txt` через `i18n.text()`. Ключ добавлять в **`en`** обязательно (источник правды); `ru` / `zh` — по мере необходимости (см. следующий пункт). Контент тоже по языкам: тексты демо — `src/demos/text/<lang>/` (тест `tests/test_demo.py`), комментарии сидов — `src/seed_text/<lang>/` (тест `tests/test_seed_i18n.py`, конвенция — `src/seed_text/README.md`), справочники — `docs/<lang>/`. Смена языка **уже посеянной** БД — `:relang <код>` (`src/relang.py`): переписывает только комментарии канонических строк сидов, пользовательские теги/команды и правленые руками комментарии не трогает. Встроенный русский текст в `seed_*.py` и базовых `demos/*.yml` — это базовый слой, не дублировать его в `en`. Команды, имена тегов, ключи настроек, имена файлов и слоган не переводятся. Ловушка YAML: ключи `off` / `n` / `N` / `on` без кавычек становятся булевыми — кавычить (сторожит тот же тест).
- **Экономия токенов: база — русская, `en`/`zh` догоняют по мере необходимости.** Массовый перевод дорог, поэтому источник правды для **контента** — русский: `docs/*.md` (и обзор `K8S_CHAINS.md` в корне), встроенные комментарии в `src/seed_*.py`, базовые `src/demos/*.yml`, корневой `README.md`, шаблоны `src/settings/ru.yml` и `src/llm_providers/ru.yml`. Правя поведение или текст, обновляй **русскую** версию; слои `docs/<lang>/`, `src/seed_text/<lang>/`, `src/demos/text/<lang>/`, `docs/<lang>/README.md`, `src/{settings,llm_providers}/<lang>.yml` — только по просьбе или когда слой реально понадобился. Полного паритета переводов не требуем: отсутствующий текст откатывается на базу. Интерфейсные каталоги `src/locales/` — исключение: там источник правды `en` (обязан быть полным), `ru`/`zh` могут отставать и падать на `en`. Строгие сторожа полноты (`tests/test_i18n.py`, `tests/test_seed_i18n.py`, `tests/test_seed_catalog.py`, `tests/test_demo_i18n.py`) на отставшем переводе валятся — тогда либо догоняют перевод (если просили), либо ослабляют сторожа вместе с правкой; перевод ради зелёного прогона не гнать.
- Тесты: `python3 -m pytest tests/ -v`. Изолированный cwd (см. `tests/conftest.py`). Сеть в тестах не дергать: `check_updates: false`.
- **Тесты по объёму правки.** По умолчанию — только затронутые файлы: `python3 -m pytest tests/test_X.py tests/test_Y.py -q`, плюс `ruff` и `basedpyright`. Полный `pytest tests/` — **только по явной просьбе** (он идёт ~20 минут): не гонять его «на всякий случай» и не перезапускать после прерывания. Если сомневаешься в охвате — спроси, прежде чем запускать весь набор: `app.py`-роутинг, `shell_env.py`, `demo.py`, схема БД — повод *предложить* полный прогон, а не сделать его молча.
- Документируй пользовательское поведение: `README.md`, `COMPACT_SUMMARY.md`, `:?`, при ручных сценариях — `test_cmd.md`. `CLAUDE.md` — для агентов.
- Коммит только по просьбе. Не коммитить `.codegraph/`, `demo_cmd.txt`, `test_ses.txt`, локальные `playbook.yml` / `*.db`. Личный `settings.yml` — **не в git** (`.gitignore`); настройки по умолчанию писать в шаблоны `src/settings/<lang>.yml` (en/ru/zh — ключи и значения синхронны, различаются только комментарии), а провайдеров LLM — в `src/llm_providers/<lang>.yml` (там язык файла задаёт ещё `answer_language` и текст офлайн-заглушки). `README.md` в корне — русский, переводы — `docs/<lang>/README.md` с тем же маркером версии (его обновляет `bump_version`).
- Не обновлять git config. Не `--force` в `main`.
- **В GitHub пушим только в `main`.** На `origin` не держим рабочих/экспериментальных веток: локальные эксперименты — можно, но результат уходит в `main` (squash/merge), а временную ветку после слияния удаляем и локально, и на `origin`. Пуш — `git push origin HEAD:main` (локальная ветка может называться иначе, напр. `autocomplite`).

## Не делать

- Не раскрывать `!` / `!!` в момент `#tag`.
- Не запускать TTY-команды из YAML-демо (`> htop` снимет TUI и будет ждать человека).
- Не класть бесконечный `loop: true` в bundled-туры (`short` / `full` / `ip`).
- Не класть `:q` в середину демо, если нужна запись хвоста; выход — `--demo-quit`.
- Не превращать клик по `--seed` в автозапуск: только вставка во ввод.
- Не ломать построчный режим и пайп: `|` и `$OUT` берутся из **сфокусированного** (иначе последнего) блока.
- Не раздувать `src/app.py` без нужды: новое — в модуль (`demo.py`, `md_viewer.py`, `update_check.py`, …), в App — маршрутизация.
- Экспорт/импорт базы — только через `src/db_transfer.py` (JSON/CSV/Markdown): одна схема и один путь записи для TUI (`:export`/`:import`) и CLI (`backup_db.py`). Внешний импорт — тот же путь (`plan_import` → `import_payload`) через `src/remote_source.py`; не заводить второй JSON-разбор и вторую запись в БД. Не заводить вторую JSON-схему и вторую SQL-запись; глобальные `id` из файлов не переносить (точный слепок — SQLite-снимок `:backup` / `backup_db.py backup`).
