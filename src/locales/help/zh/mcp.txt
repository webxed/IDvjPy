[bold]:? mcp — 供 AI 客户端使用的标签库（MCP 服务器，只读）[/bold]

  python3 mcp_server.py        - 启动 MCP 服务器（stdio；由客户端启动）
  python3 mcp_server.py --shell-history
                - …并允许 `search_history` 也读取 shell 自身的历史文件
                （bash/zsh/fish/atuin）
  --data-dir / --db / --instance - 读取哪个库与历史：与 TUI 相同的规则
                （启动目录的 settings.yml → $IDVJPY_DATA_DIR → 系统目录；
                `database_tags_file`；history_<instance>.txt）

  MCP（Model Context Protocol）是 AI 客户端（Claude Code、Cursor 等）接入外部
  工具的方式：客户端自行启动该进程，并通过 stdin/stdout 用 JSON-RPC 通信，每行
  一条消息。不开放任何端口 —— 应用从不监听（`:? vars`）。接入示例：

    claude mcp add idvjpy -- python3 /path/to/IDvjPy/mcp_server.py

    {"mcpServers": {"idvjpy": {"command": "python3",
                               "args": ["/path/to/IDvjPy/mcp_server.py"]}}}

  工具 —— 全部只读：库不会被修改，命令不会被执行。

    search_commands(query, tag?, limit?) - 在命令文本与注释中做子串匹配，如同
                `?text`；返回 `tag\[tid]  命令  # 注释`
    list_tags(include_hidden?)  - 标签及其有效命令数与注释
    get_tag(tag, limit?)        - 某个标签的全部有效命令（如同 `?tag`）
    search_history(query?, source?) - 你实际输入过的内容：`session`
                （history_<instance>.txt）、`shells`（需要 --shell-history）或 `all`
    library_stats()             - 规模与运行计数：真正在用的是哪些

  服务器刻意做不到的事：

  - 写入：没有 `#tag`、`#tag-`，不能修改库。给 AI 客户端写入权，一次提示注入
    就能毁掉整个库
  - 执行命令（`:run`、`!tag\[tid]`）—— 执行留在 TUI 里，由人来按 Enter（`run:manual`
    这一步存在的同一理由）
  - 读取密钥：secrets_<instance>.json 不会被打开，`$$` 的值只存在于会话中 ——
    库里和历史文件里都没有

  隐私：工具返回的一切都会发给接入的 AI 客户端，库与历史会随该客户端的发送范围
  离开本机。因此不要把密钥写进标签（用 `$$`），也不要存进保存的命令里。启动时
  服务器会向 stderr 写一行，说明它读取哪个库与历史；stdout 只承载 JSON-RPC，
  否则客户端无法解析这个流。

  适用场景：「查看 pod 日志我用的是哪条命令？」—— 代理会在你自己的库里找到
  `kpod\[tid]`，而不是编一条命令。
