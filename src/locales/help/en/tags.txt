[bold]:? tags — database queries and references[/bold]

  ?          - Query database (? tags, ?<tag>, ?? grouped; ?? lists hidden tags)
               Typing `?` lists tags with a hint (commands count + tag comment):
               letters filter, Tab/Enter insert `?tag` (Enter again runs it),
               a click on the row runs the query at once. `??` is left as is.
               ?text (2+ chars, no such tag) = search commands/comments across all tags;
               rows: <id> tag[tid]; Esc → input, then Enter runs via !ID
               In ?? click a tag → insert `!tag ` / `!tag[tid] ` at the cursor
               (does not replace the line; terminal_mouse). Ctrl+click or
               double-click on `!tag[tid]` inserts it AND runs it right away
               (exactly as typing the ref and pressing Enter twice; a
               tid-less `!tag ` is only inserted). Esc → input, then Enter.
  !tag / !tag[tid] - Type ! to list tags [file, kube, log]; Tab picks a tag
               Then commands show as `<id> tag[tid]  full command`; Tab inserts `!tag[tid]`
               Compose pipes/saves: `#file !file[1] | !file[2]` (preview expands refs)
  !N         - Execute command by ID from last query

  Pins       - `:pin add TAG…`, `:pin rm TAG…`, `:pin clear`, `:pin list`;
               stored in `pins_<session>.json` in the data directory, not exported.
               `:tags pinned` filters the catalog; pinned tags appear first.
               Scope still hides tags outside this session's visibility.
  Metadata  - `:tagmeta TAG` shows metadata; passing JSON replaces it, `{}` clears.
               Fields: risk, utilities, os, interactive, topic, example. Descriptive
               only; metadata is included in JSON transfer. Canonical seeds annotate
               their own tags (git, kpod, sqlite, vault, …), so `:tags vcs` works
               right after `--seed` without manual `:tagmeta`.


  Catalog    - `:tags [filter]` searches live tags, descriptions, and metadata;
               filtering respects the current session scope.
               `:tagmeta TAG` shows metadata; `:tagmeta TAG '{"risk":"low","utilities":["git"],"os":["linux"],"interactive":false,"topic":"inspect","example":"git status"}'` replaces it; `{}` clears.
               Fields: risk (low/medium/high/critical), utilities/os (string arrays),
               interactive (boolean), topic/example (strings). JSON export includes
               tag_metadata; metadata is descriptive and does not affect execution.

  Scope      - Per-window tag filter: :scope add git (only that handbook),
               :scope rm k8s (hide it), :scope clear / :scope all (everything).
               Affects lists and hints only: ?, ??, ?text, ! / Tab completions and
               the screensaver ticker. Explicit refs (?tag, !tag[tid], :run,
               :stats, :export) ignore the filter, so saved chains never break.
               Kept per session (scope_<instance>.json); the window title shows
               the marker (`· only git`). Without arguments :scope reports state.
