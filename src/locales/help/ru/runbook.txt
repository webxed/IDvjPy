[bold]Runbook — полуавтоматическая цепочка команд (:run)[/bold]

Одна цепочка, несколько команд: шаги auto выполняются один за другим и ожидаются,
а цепочка останавливается и ждёт вас там, где нужны значение или решение.

[bold]Использование[/bold]
  :run <tag>              - шаги этого тега в порядке tid (режимы из директив run:)
  :run <tag> --step       - пошагово: каждый шаг ждёт вашего Enter
  :run chain.yml          - шаги из YAML (manual: / prompt: в шаге)
  :run <tag|file> --dry   - показать план и ничего не запускать
  :run stop               - остановить цепочку (как Esc)
  :run                    - использование + теги с директивами run:

[bold]Режимы шага[/bold]
  auto   - строка вставляется во ввод, выполняется и ожидается; exit ≠ 0
           останавливает цепочку (если шаг не говорит run:continue)
  manual - строка вставляется, и цепочка ждёт: правьте при необходимости и жмите
           Enter (пустой Enter пропускает шаг; Esc останавливает цепочку)
  prompt - ввод пуст: наберите всю строку и нажмите Enter (например, значение
           или целую строку `$$VAULT_TOKEN=…` — секреты остаются замаскированными)

[bold]Директивы в комментарии команды тега[/bold] (первые токены; остальное —
подсказка, показываемая в ?? — например, `#vapprole=5=run:manual issue secret_id`):
  run:auto | run:manual | run:prompt
  run:pause=SEC      - пауза после того шага
  run:continue       - сбой этого шага не останавливает цепочку
  run:stop           - остановка при сбое (по умолчанию)
Директивы в комментарии ТЕГА задают умолчания для всех его шагов (пауза, политика
сбоя); режим шага всегда берётся из собственного комментария команды.
Тег вообще БЕЗ директивы run: получает предупреждение в плане — иначе каждый шаг
шёл бы auto, включая мутации; помечайте мутирующий шаг run:manual.
`--step` убирает эту заметку (каждый шаг всё равно ждёт вашего Enter).

[bold]Исходник YAML[/bold] (`:playbook` пишет совместимый файл)
  title: vault approle
  pause: 0.3                 # пауза между шагами auto
  steps:
    - echo one               # строка = шаг auto
    - type: vault read …     # то же, развёрнуто
      wait_command: true
    - type: $ROLE=            # строка-префикс: дописать значение после =
      manual: true           # ждать Enter (строка предзаполнена)
      caption: role name     # подсказка в плане и в заголовке шага
    - prompt: AppRole name   # ждать строку, набранную с нуля
    - echo checked

Путь к YAML относителен cwd процесса (запущен алиасом из домашнего каталога —
это он и есть); тег живёт в БД каталога данных и потому надёжнее между сессиями.
`:playbook` также пишет playbook.yml в cwd.

[bold]Пока идёт[/bold]
  подзаголовок показывает `RUN <chain> · 3/8 · manual · Esc stops`; сначала план
(с режимами) печатается в журнал. Esc останавливает цепочку; саму выполняющуюся
команду останавливают через F4 / :kill. Вызовы `:run` записываются в
history_<instance>.txt (↑ / :h), но не в подсказки, а шаги, вставленные runbook,
не записываются `:playbook`.

Цепочка — не тур: шаги выполняются по-настоящему, в той же сессии и журнале,
каждый виден со своим выводом. Интерактивные программы (`htop`, `vault login`
с запросом пароля) — не шаги runbook; для них используйте `> cmd`.
