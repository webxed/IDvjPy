[bold]Vault — хранилище секретов с шифрованием по паролю (`:vault`)[/bold]

  Долговременное хранилище секретов — в отличие от `$$NAME=…` (тот живёт только
  сессию). Файл — `vault.json.enc` в каталоге данных (0600): заголовок открыт,
  записи зашифрованы (scrypt + AES-256-GCM). Неверный пароль и испорченный файл
  дают явную ошибку, а не мусор на экране.

  Разблокировать раз за сессию; пароль остаётся только в памяти:

    :vault init               создать хранилище (пароль спрашивается дважды)
    :vault unlock | lock      разблокировать на сессию / забыть
    :vault                    файл, замок, имена записей (значения — никогда)

  Работа с записями:

    :vault add NAME [hint]    добавить или заменить значение (ввод маскирован)
    :vault gen NAME [len]     сгенерировать случайное значение
    :vault list               имена и подсказки
    :vault rm NAME            удалить запись

  Как достать значение — на экран значение не печатается:

    :vault cp NAME               → в буфер обмена (чистится при выходе из TTY и через 60 с)
    :vault use NAME [VAR]        → $VAR в окружении этой сессии
    :vault exec NAME[=VAR] -- cmd    $VAR в env дочернего процесса, не в argv
    :vault stdin NAME -- cmd         значение уходит команде на stdin

  `exec` сам подбирает переменную для известных программ (sshpass → SSHPASS,
  psql → PGPASSWORD, mysql/mysqldump → MYSQL_PWD, vault → VAULT_TOKEN, restic,
  borg, redis-cli); для остальных укажите `NAME=VAR` явно.

  Правила: значения не попадают в журнал, `:o`, `↑`, `history_*.txt`, `:send` и
  `:export`; пока хранилище разблокировано, они маскируются как `$$`-секреты.
  `cp` — самое слабое звено: буфер могут прочитать другие программы. Нужен пакет
  `cryptography` (`pip install cryptography`); без него остальное приложение
  работает как обычно.

  Примеры: `:vault init`, `:vault add SSH_PROD прод ssh`, `:vault cp SSH_PROD`
  и затем `> ssh …` (вставить), либо `:vault exec sshpass -- ssh user@host`.
