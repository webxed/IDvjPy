[bold]Vault — хранилище секретов с шифрованием по паролю (`:key`)[/bold]

  Долговременное хранилище секретов — в отличие от `$$NAME=…` (тот живёт только
  сессию). Файл — `vault.json.enc` в каталоге данных (0600): заголовок открыт,
  записи зашифрованы (scrypt + AES-256-GCM). Неверный пароль и испорченный файл
  дают явную ошибку, а не мусор на экране.

  Разблокировать раз за сессию; пароль остаётся только в памяти:

    :key init               создать хранилище (пароль спрашивается дважды)
    :key unlock | lock      разблокировать на сессию / забыть
    :key                    файл, замок, имена записей (значения — никогда)

  Работа с записями:

    :key add NAME [hint]    добавить или заменить значение; в окне есть и комментарий
    :key comment NAME [текст]  править только комментарий (значение остаётся);
                              `;` — разделитель ссылок, без текста — показать, `-` — снять
    :key gen NAME [len]     сгенерировать случайное значение
    :key list               имена и комментарии (каждая ссылка — своей строкой)
    :key find ТЕКСТ         поиск по имени и комментарию без учёта регистра
                              (алиас `search`); значения не ищутся и не показываются
    :key rm NAME            удалить запись

  Как достать значение — на экран значение не печатается:

    :key cp NAME               → в буфер обмена (чистится при выходе из TTY и через 60 с)
    :key use NAME [VAR]        → $VAR в окружении этой сессии
    :key exec NAME[=VAR] -- cmd    $VAR в env дочернего процесса, не в argv
    :key stdin NAME -- cmd         значение уходит команде на stdin
    :key unuse [NAME|*]            снять выданные переменные (NAME или `*` — все)

  `exec` сам подбирает переменную для известных программ (sshpass → SSHPASS,
  psql → PGPASSWORD, mysql/mysqldump → MYSQL_PWD, vault → VAULT_TOKEN, restic,
  borg, redis-cli); для остальных укажите `NAME=VAR` явно. Сама программа должна
  быть установлена (`apt install sshpass` и т.п.) — хранилище даёт только
  переменную. Для sshpass нужен `-e` (берёт `$SSHPASS`), а не `-p`: `-p` выносит
  значение в argv, где его видно в `ps`.

  Комментарий — пометка к записи: куда относится ключ, ссылки, напоминание:
  `:key comment SSH_PROD прод ssh;https://gitlab.example/proj;ssh://u@host`.
  Это **не** секрет и не маскируется: он попадает в журнал, `↑` и `history_*.txt`
  как набран — не вставляйте в комментарий само значение (и URL с токеном).
  В сообщениях `cp`/`use` комментарий показан рядом со именем.

  Правила: значения не попадают в журнал, `:o`, `↑`, `history_*.txt`, `:send` и
  `:export`; пока хранилище разблокировано, они маскируются как `$$`-секреты, и
  переменные из `use` тоже маскируются в выводе — даже после замка. `cp` — самое
  слабое звено: буфер могут прочитать другие программы. Нужен пакет
  `cryptography` (`pip install cryptography`); без него остальное приложение
  работает как обычно.

  [bold]TOTP-коды:[/bold] коды двухфакторной аутентификации без телефона. Сам
  секрет хранится зашифрованным как любая другая запись; на экран выходит только
  текущий одноразовый код, поэтому секрет не печатается:

    :key add GITHUB --totp      вставить base32-секрет или ссылку otpauth://
    :key totp GITHUB            живой код: обновляется каждую секунду, Enter/`c`
                                  копирует свежий код, Esc закрывает без копии

  Значением `--totp` может быть голый base32-ключ (`jbsw y3dp ehpk 3pxp`) или
  ссылка из QR-кода (`otpauth://totp/Issuer:acct?secret=…&issuer=…&digits=…`):
  число цифр (6–8), период и алгоритм (SHA1/256/512) хранятся у записи. Код —
  **не** секрет: его можно показывать и копировать (он живёт 30 с и может попасть
  в журнал и `:o`, в отличие от секрета). Счётчик берётся из системных часов —
  неверные часы дают неверные коды. Оба фактора оказываются в одном хранилище —
  удобно для кодов под рукой, но не повод доверять чужому паролю.

  [bold]Автоблокировка:[/bold] хранилище запирается само после `vault_idle_lock`
  минут без обращений (по умолчанию 15) — пароль забывается, и следующее чтение
  секрета снова его спросит. Переменные от `:key use` при этом **остаются** в
  окружении (снять — `:key unuse`). `:key autolock N` меняет срок на сессию,
  `0` — выключает; `vault_idle_lock: 0` в settings.yml — навсегда.

  Примеры: `:key init`, `:key add SSH_PROD прод ssh`, `:key cp SSH_PROD`
  и затем `> ssh …` (вставить), либо `:key exec SSH_PROD -- sshpass -e ssh user@host`
  (нужен установленный sshpass).
