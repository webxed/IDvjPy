[bold]:? md — markdown-справочники, документы и поиск[/bold]

  :md <файл|путь>[#L<n>] - открыть markdown с форматированием: имя справочника
                репозитория или явный путь (например, файл из хранилища Obsidian);
                `#L<n>` открывает сразу на строке n (как на GitHub). Esc закрывает,
                `y` копирует полный путь (в форматированном виде — ещё и клик по
                имени в шапке). Записывается в историю (↑ / `:h`). Файлы длиннее
                `md_render_lines` (по умолчанию 1000) открываются исходником в
                Line-API просмотрщике — мгновенно, с поиском `/`, `n`/`N` и `#L<n>`
  :rg <regex> [каталог] - поиск по markdown-файлам (ripgrep, иначе встроенный сканер
                с подсказкой установки). «Умный регистр», лимит 200 совпадений,
                скрытые/служебные каталоги пропускаются. База: [каталог] → `md_dir`
                → cwd. Результаты кликабельны (`путь:строка` открывает просмотрщик
                на этой строке), `:rg <N>` — N-й результат (с 1). `:rg` и `:md`
                пишутся в историю (↑ / `:h`), но в подсказках не предлагаются

[bold]Документы: не только markdown[/bold]

  «Текст или документ» решает [bold]содержимое[/bold], а не расширение: PDF по
  сигнатуре, ZIP офисного пакета (docx/xlsx/pptx, odt/ods/odp, epub), OLE2 (старые
  .doc/.xls/.ppt), RTF, NUL-байты. Текстовый файл открывается как есть — конвертер
  не нужен и не вызывается.

  Конвертер берётся из `md_converter` (settings.yml), иначе — первый установленный:
    1. [bold]anydoc[/bold] (`pip install firecrawl-anydoc`) — рекомендуем.
       Rust-расширение [bold]без зависимостей[/bold], колесо ~3 МБ, Python 3.10+.
       Формат определяет по содержимому, PDF читает локально. Покрывает doc/docx/docm,
       ppt/pps/pot/pptx/pptm, xls/xlsx/xlsm/xlsb, odt/ods/odp, rtf, epub, csv, pdf.
    2. [bold]markitdown[/bold] (`pip install "markitdown[all]"`) — Python-пакет, тянет
       pandas/lxml/pdfplumber и прочее; берём, если он уже установлен.
    3. [bold]pandoc[/bold] — системный пакет; документы читает консервативно
       (в основном docx/odt/rtf), зато есть почти везде и знает много форматов.
  Своя команда тоже годится: `md_converter: "my-tool --md"` — файл дописывается
  последним аргументом, markdown ожидается в stdout. Разово: `$IDVJPY_MD_CONVERT`.
  Явно заданный конвертер [bold]не подменяется[/bold] другим: нет инструмента — явная ошибка.

[bold]Скан-PDF: локальный OCR[/bold]

  Если текстового слоя нет (anydoc сообщает `needs_ocr`, либо конвертер вернул пусто),
  файл — PDF и есть движок, `:md` накладывает текстовый слой через [bold]ocrmypdf[/bold]
  и читает PDF заново. Наружу ничего не уходит: конвертация и распознавание локальные.

  Установка: `apt install ocrmypdf` (Debian/Ubuntu) · `dnf install ocrmypdf tesseract-osd`
  (Fedora) · `apk add ocrmypdf` (Alpine) · `brew install ocrmypdf` (macOS/Linux) ·
  `pip install ocrmypdf` (нужен системный [bold]tesseract[/bold] 4.1.1+ и языковые пакеты к нему).
  [bold]Язык скана[/bold] задаёт tesseract, по умолчанию — английский: для русского ставят
  пакет (`apt install tesseract-ocr-rus`) и указывают язык — `md_ocr: ocrmypdf -l rus`
  (для смешанных документов — `-l rus+eng`). Без пакета со скана выходит латиница
  («Квартальный отчёт» → «KBapTaJIbHbIN OTYET») или сообщение о нехватке языка.

  Ключ `md_ocr`: пусто — автопоиск `ocrmypdf`; `off`/`none`/`no`/`false`/`0` — не
  распознавать (останется сообщение «нужен OCR»); `on`/`auto` — как пусто; своя команда —
  свои флаги (например, `ocrmypdf -l rus+eng --rotate-pages`). Разово: `$IDVJPY_MD_OCR`.
  Свои флаги `:md` добавляет только `ocrmypdf` и только если режим не задан вручную:
  `--skip-text` (страницы с текстом не трогаем — без него ocrmypdf откажется),
  `--optimize 0 --output-type pdf` (нужен только текст, без сжатия и PDF/A) и
  `--sidecar`: текстовый файл рядом с PDF — если конвертер откажется читать
  «картиночный» PDF с OCR-слоем, `:md` покажет распознанный текст оттуда.
  Распознавание идёт в фоне, таймаут — 300 с.

[bold]Кэш, настройки, сообщения[/bold]

  Результат кэшируется в `<data>/mdcache/<имя>-<ключ>.md` (ключ — путь, mtime, размер,
  конвертер и команда OCR): повторное `:md` мгновенно, а `#L<n>`, поиск `/` и `y`
  работают как для обычного файла. Каталог можно удалить руками — сконвертируется заново
  (скан распознается тоже). Кэш переживает удаление конвертера.

  Что значит сообщение: «нужен OCR» — движка нет, есть подсказка установки; «нет данных
  языка» — поставить `tesseract-ocr-<язык>`; «конвертер недоступен» — проверить
  `md_converter`; «не удалось» — в тексте строка stderr инструмента; «пусто» —
  конвертер и OCR не дали текста; «таймаут».

  Настройки: `md_dir` (база `:rg`), `md_render_lines` (порог форматирования),
  `md_converter` (чем конвертировать) и `md_ocr` (чем распознавать).
