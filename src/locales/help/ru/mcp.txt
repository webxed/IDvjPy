[bold]:? mcp — библиотека тегов для AI-клиентов (MCP-сервер, только чтение)[/bold]

  python3 mcp_server.py        - Запустить MCP-сервер (stdio; запускает его клиент)
  python3 mcp_server.py --shell-history
                - …и разрешить `search_history` читать ещё и собственные файлы
                истории оболочки (bash/zsh/fish/atuin)
  --data-dir / --db / --instance - какую библиотеку и историю читать: те же
                правила, что у TUI (settings.yml в каталоге запуска →
                $IDVJPY_DATA_DIR → системный каталог; `database_tags_file`;
                history_<instance>.txt)

  MCP (Model Context Protocol) — так AI-клиент (Claude Code, Cursor, …) подключает
  внешний инструмент: клиент сам запускает этот процесс и говорит с ним JSON-RPC
  по stdin/stdout, по одному сообщению на строку. Порт не открывается — приложение
  не слушает (`:? vars`). Подключение:

    claude mcp add idvjpy -- python3 /путь/к/IDvjPy/mcp_server.py

    {"mcpServers": {"idvjpy": {"command": "python3",
                               "args": ["/путь/к/IDvjPy/mcp_server.py"]}}}

  Инструменты — все только на чтение: библиотека не меняется, команды не выполняются.

    search_commands(query, tag?, limit?) - подстрока по тексту команд и
                комментариям, как `?text`; отвечает `tag\[tid]  команда  # комментарий`
    list_tags(include_hidden?)  - теги с числом живых команд и комментариями
    get_tag(tag, limit?)        - все живые команды одного тега (как `?tag`)
    search_history(query?, source?) - что вы на самом деле набирали: `session`
                (файл history_<instance>.txt), `shells` (нужен --shell-history)
                или `all`
    library_stats()             - размеры и счётчики запусков: что реально работает

  Чего сервер намеренно не умеет:

  - записывать: ни `#tag`, ни `#tag-`, ни правок библиотеки. AI-клиент с правом
    записи — это одна инъекция в промпт до разрушенной библиотеки
  - выполнять команды (`:run`, `!tag\[tid]`) — запуск остаётся в TUI, где Enter
    нажимает человек (поэтому и существует шаг `run:manual`)
  - читать секреты: secrets_<instance>.json не открывается, а значения `$$` живут
    только в сессии — их нет ни в библиотеке, ни в файле истории

  Приватность: всё, что вернули инструменты, уходит подключённому AI-клиенту —
  библиотека и история уезжают так далеко, как их отправит этот клиент. Поэтому
  секреты в теги не пишем (для них есть `$$`) и не храним их в сохранённых
  командах. При старте сервер пишет одну строку в stderr — какую библиотеку и
  историю он читает; в stdout уходит только JSON-RPC, иначе клиент не разберёт
  поток.

  Пригодится для: «какая у меня команда, чтобы смотреть логи пода?» — агент найдёт
  `kpod\[tid]` в вашей же библиотеке, а не выдумает команду.
